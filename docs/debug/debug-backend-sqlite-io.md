# [OPEN] backend-sqlite-io

## 症状
- 后端多次热重启后，启动阶段出现 `sqlite3.OperationalError: disk I/O error`
- 烧录任务执行过程中被后端进程中断
- 当前需要先恢复稳定的单实例后端，再继续烧录链路验证

## 当前假设
- 假设 1：存在多个 `run_backend.py` 并发进程，同时持有同一 SQLite / WAL 文件导致 I/O 异常
- 假设 2：`app_data.db-wal` 或 `app_data.db-shm` 处于异常状态，单实例重启前未正确回收
- 假设 3：后端恢复任务线程在启动时立即访问数据库，和主进程初始化竞争导致错误暴露
- 假设 4：数据库文件所在目录权限或文件属性异常，导致重启后新进程无法稳定打开
- 假设 5：前面连续 Stop/Start 导致旧 Python 子进程未完全退出，端口与数据库状态短时不一致

## 计划
- 收集后端进程、8000 端口、SQLite 主文件/WAL/SHM 文件状态
- 在不改业务逻辑的前提下做单实例干净重启
- 如果单实例仍报错，再决定是否做最小环境修复
