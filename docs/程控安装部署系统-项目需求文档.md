## 2. 项目概述

### 2.1 项目背景

嵌入式设备的软件烧录、操作系统安装、异常注入和通信协议验证通常分散在多个工具和人工流程中，存在以下典型问题：

- 制品分散，版本来源不统一，难以追溯。
- 板卡、烧录器、脚本、协议配置相互独立，执行链路割裂。
- 安装、烧录、测试、异常验证的数据无法形成统一闭环。
- 过程记录依赖人工登记，审计追踪和复盘效率低。
- 权限边界不清晰，跨角色协作存在误操作和越权风险。

为解决上述问题，建设桌面端一体化的程控安装部署系统，面向嵌入式软硬件测试、烧录安装、制品管理和系统管理场景，形成“制品管理-任务执行-结果沉淀-日志追溯-权限治理”的统一作业平台。

### 2.2 建设目标

- 建立统一的制品接入与版本使用入口，实现软件包、镜像、脚本的集中管理。
- 建立标准化的烧录安装执行流程，实现任务创建、参数配置、执行监控和结果留痕。
- 建立嵌入式设备异常注入与协议验证能力，支撑研发和测试阶段的可靠性验证。
- 建立统一的用户、角色、菜单、按钮、数据权限体系，确保可见即可管、可管可审。
- 建立登录日志、操作日志、履历记录和消息通知机制，满足审计、追踪和问题定位需求。
- 形成可持续扩展的桌面端产品底座，支持后续接入更多烧录器、协议类型、仓库源和执行策略。

### 2.3 项目范围

#### 2.3.1 业务覆盖范围

- 嵌入式软件制品同步与项目级仓库管理
- 产品、烧录器、脚本等基础资产管理
- 烧录安装任务配置、执行、结果回溯
- 异常注入任务编排、实时监控、状态管理
- 通信协议连接、发送、接收、日志展示与执行记录
- 用户、角色、菜单权限、数据权限和审计日志管理

#### 2.3.2 系统功能边界

本期纳入范围：

- Electron 桌面客户端
- FastAPI 本地/部署式业务服务
- SQLite 数据持久化
- 基于角色的访问控制
- 与 CodeArts 制品仓库的同步集成
- 本地消息中心、个人中心、健康检查

本期不纳入范围：

- 移动端应用
- 公有云 SaaS 多租户能力
- 外部 ERP/MES/PLM 深度集成
- 大规模分布式设备远程集群调度
- 面向第三方开放的公共 API 平台

### 2.4 预期价值与收益

- 提升交付效率：减少手工配置、重复录入和跨工具切换。
- 提升版本可控性：统一制品来源、路径、摘要信息和版本追溯。
- 提升测试覆盖度：将异常注入和协议验证纳入统一作业平台。
- 提升审计能力：关键操作留痕、权限分级、结果闭环可追踪。
- 降低运维成本：桌面化部署、数据本地化、依赖较轻、交付灵活。
- 提升组织协同效率：产品、研发、测试、运维围绕统一流程协作。

## 3. 业务需求

### 3.1 业务定位

PCIDS 定位为面向嵌入式软件安装部署与验证场景的桌面端综合作业平台，服务于研发、测试、实施与运维人员，解决“软件制品、硬件资源、执行过程、验证结果、权限治理”五类核心对象的统一管理问题。

### 3.2 业务角色与职责划分

| 角色 | 核心职责 | 关注点 |
|---|---|---|
| 项目管理员 | 系统配置、权限分配、项目初始化、关键数据维护 | 权限边界、配置正确性、审计留痕 |
| 制品管理员 | 制品仓库同步、项目信息维护、成员及权限管理 | 版本准确性、仓库可达性、摘要信息完整性 |
| 测试工程师 | 创建烧录/安装/异常注入/协议验证任务并分析结果 | 执行效率、配置便捷性、日志与报告完整性 |
| 研发工程师 | 关注异常复现、协议数据、版本一致性和调试信息 | 诊断信息、参数透明度、可追溯性 |
| 设备管理员 | 维护烧录器、脚本、硬件资源状态 | 设备在线性、可用性、资源冲突控制 |
| 审计/管理人员 | 查看日志、履历和执行记录 | 操作留痕、权限合规、问题追责 |

### 3.3 Stakeholders 权责矩阵

| Stakeholder | 责任 | 决策事项 | 输出物 |
|---|---|---|---|
| 产品经理 | 定义业务流程、功能边界、验收标准 | 优先级、范围控制、版本目标 | PRD、原型、迭代计划 |
| 技术负责人 | 方案设计、技术选型、质量把控 | 架构、接口、扩展策略 | 设计文档、技术方案 |
| 前端研发 | 客户端界面、交互、权限显隐 | 页面实现、用户体验收口 | 前端代码、联调说明 |
| 后端研发 | 业务接口、数据模型、权限校验 | 数据结构、接口协议、审计策略 | API、模型、脚本 |
| 测试工程师 | 测试用例、回归验证、缺陷管理 | 覆盖范围、阻塞项判定 | 用例、报告、缺陷单 |
| 运维/实施 | 部署、升级、问题排查 | 环境交付、运行保障 | 部署文档、巡检记录 |
| 业务代表 | 场景确认、结果验收 | 业务规则是否满足 | 验收意见 |

### 3.4 全链路业务流程

#### 3.4.1 主业务闭环

1. 管理员初始化用户、角色、菜单权限和数据权限。
2. 制品管理员配置 CodeArts 仓库连接并同步项目制品。
3. 设备管理员维护产品、烧录器、脚本等基础资产。
4. 测试工程师基于制品、资产和目标设备创建烧录安装任务。
5. 系统执行任务并记录过程日志、执行状态和一致性结果。
6. 测试工程师针对目标继续发起异常注入和通信协议验证。
7. 系统沉淀履历记录、登录日志、操作日志和消息通知。
8. 管理者通过日志与记录完成追踪、审计和复盘。

#### 3.4.2 典型业务场景

| 场景 | 触发条件 | 核心诉求 | 成功标准 |
|---|---|---|---|
| 制品同步 | 新版本发布或仓库变更 | 快速拿到指定项目制品及其元数据 | 同步成功、版本/路径/摘要完整 |
| 烧录安装 | 板卡交付、软件部署、版本升级 | 低误配置、高可视化的任务执行 | 执行成功、结果可回溯 |
| 异常注入 | 可靠性、容错性验证 | 复现断电/存储/网络/权限异常 | 异常过程可监控、状态可管理 |
| 协议验证 | 设备联调、接口调试 | 快速验证 CAN/CAN FD/串口/以太网/GPIO 通信 | 建连成功、报文可见、记录留存 |
| 审计追踪 | 问题定位、权限核查 | 找到谁在何时做了什么 | 日志完整、查询可用、不可抵赖 |

### 3.5 业务规则

#### 3.5.1 通用规则

- 所有业务数据均需保留创建人、修改时间、状态等基础信息。
- 所有关键写操作应写入操作日志。
- 页面访问与页面内操作权限必须解耦，查看权限单独配置。
- 列表、详情、执行记录、日志查询均需支持分页。
- 所有删除、清空、重置类高风险操作必须二次确认。

#### 3.5.2 制品管理规则

- 制品同步必须指定项目、仓库或制品来源配置。
- 同步结果需保存版本、路径、摘要、发布时间等信息。
- 当同一制品同时存在服务器和本地副本时，应区分展示两个路径。
- 同步失败时需保留失败原因，便于排查。

#### 3.5.3 执行类任务规则

- 创建任务前必须完成必要参数校验。
- 执行中的任务必须能展示实时状态或过程日志。
- 已完成任务需保留结果状态、执行时间、执行人和关键参数快照。
- 特定冲突场景应支持强制覆盖提示或阻断。

#### 3.5.4 安全与权限规则

- 管理员拥有全量权限。
- 普通角色必须按页面查看权限、按钮权限、数据权限分别配置。
- 任意按钮权限被授予时，系统应自动补齐对应页面查看权限。
- 无查看权限时，菜单不可见，直接访问接口应返回拒绝。

### 4.1 功能结构总览

| 一级模块 | 二级模块 |
|---|---|
| 认证与入口 | 登录、退出、个人中心、消息中心、工作台 |
| 制品仓库 | 仓库同步、项目管理、项目成员、权限设置、制品详情 |
| 资产管理 | 产品管理、烧录器管理、脚本管理 |

| 系统管理 | 用户管理、角色管理、登录日志、操作日志 |

### 4.2 权限模型基线

#### 4.2.1 权限分类

- 页面查看权限：`xxx:view`
- 页面内操作权限：如 `add/edit/delete/execute/export/clear/download/sync`
- 数据权限：全部数据、所属项目数据、可扩展的自定义范围

#### 4.2.2 权限控制要求

- 菜单显示基于页面查看权限控制。
- 页面内按钮、操作入口、提交动作基于操作权限控制。
- 后端接口必须进行同等权限校验，不能仅依赖前端显隐。
- 角色权限树以菜单为根节点，其下展示查看权限和操作权限。

### 4.3 模块详细需求

#### 4.3.1 登录认证

**目标**

- 提供系统统一认证入口，完成用户身份识别和会话建立。

**核心用例**

| 用例 | 说明 |
|---|---|
| 用户登录 | 输入用户名和密码，成功后进入首页 |
| 退出登录 | 清理本地会话并回到登录页 |
| 获取当前用户信息 | 登录后拉取个人信息、权限和菜单 |
| 修改密码 | 在个人中心完成密码更新 |
| 上传头像 | 更新用户头像资源 |

**操作流程**

1. 用户输入账号密码。
2. 系统校验身份并签发 Token。
3. 客户端拉取用户信息、权限、菜单、消息。
4. 成功进入具备访问权限的默认页面。

**输入输出规则**

- 输入：用户名、密码。
- 输出：Token、用户信息、角色权限、菜单树。
- 异常输出：账号不存在、密码错误、账号被禁用、Token 失效。

**权限要求**

- 登录页匿名可访问。
- 退出登录、修改密码、上传头像需已登录。

#### 4.3.2 工作台

**目标**

- 提供系统概览、快捷入口和消息聚合能力。

**核心用例**

| 用例 | 说明 |
|---|---|
| 查看概览统计 | 查看任务总量、趋势、分布等统计信息 |
| 快捷进入模块 | 从工作台快速进入常用业务页面 |
| 查看消息中心 | 查看系统消息及未读数 |

#### 4.3.3 制品仓库

**目标**

- 统一管理软件制品同步、仓库项目信息和项目成员权限。

**核心用例**

| 用例 | 说明 |
|---|---|
| 配置仓库连接 | 配置 CodeArts 访问参数 |
| 同步制品 | 拉取项目制品、版本、摘要和路径 |
| 新建项目 | 建立项目级仓库配置 |
| 编辑/删除项目 | 维护项目基础信息 |
| 查看制品详情 | 查看版本、路径、摘要、发布时间 |
| 管理成员 | 邀请成员、设置用户组 |
| 配置项目权限 | 设置项目级权限范围 |

**操作流程**

1. 管理员创建或维护项目仓库配置。
2. 制品管理员执行同步。
3. 系统拉取仓库列表、制品详情与摘要信息。
4. 用户浏览目录树与制品详情，并可触发下载等操作。

**输入输出规则**

- 输入：仓库标识、项目 ID、用户凭据、同步参数。
- 输出：制品树、制品详情、文件路径、摘要、成员列表。
- 当制品存在服务器下载路径和本地下载路径时，详情需分别展示。

**权限要求**

- 查看：`repository:view`
- 操作：`repository:add`、`repository:edit`、`repository:delete`、`repository:sync`、`repository:download`

**输入输出规则**

**权限要求**

#### 4.3.5 烧录器管理

**目标**

**核心用例**

| 用例 | 说明 |

#### 4.3.6 脚本管理

**目标**

- 管理烧录/安装脚本及其关联关系。

**核心用例**

| 用例 | 说明 |
|---|---|
| 新增脚本 | 录入脚本类型、内容、关联 IDE/产品/烧录器 |
| 编辑脚本 | 更新脚本内容与绑定关系 |
| 启用/禁用脚本 | 控制脚本是否可用于任务 |
| 查看脚本 | 查看脚本元数据与历史修改 |

**输入输出规则**

- 输入：脚本名称、脚本类型、脚本内容、关联 IDE、关联产品、关联烧录器。
- 输出：脚本列表、启用状态、关联关系。

**权限要求**

- 查看：`script:view`
- 操作：`script:add`、`script:edit`、`script:delete`

#### 4.3.7 烧录安装管理

**目标**

- 提供统一的烧录安装任务编排与执行管理能力。

**核心用例**

| 用例 | 说明 |
|---|---|
| 创建任务 | 选择软件版本、目标板卡、脚本、烧录器和参数 |
| 执行任务 | 启动烧录/安装过程 |
| 查看任务详情 | 查看步骤日志、进度、执行结果 |
| 查看一致性报告 | 查看软件版本一致性判定 |
| 强制覆盖 | 对存在风险的覆盖操作给出确认 |

**操作流程**

1. 选择制品和版本。
2. 选择目标板卡、脚本、烧录器。
3. 配置执行参数并提交。
4. 执行过程中展示日志、进度和结果。
5. 完成后生成一致性报告和履历。

**输入输出规则**

- 输入：目标设备、软件版本、脚本、烧录器、执行参数。
- 输出：任务编号、执行状态、步骤日志、一致性结果。

**权限要求**

- 查看：`task:view` 或 `burning:view`
- 操作：`task:add`、`task:execute`、`task:delete`

#### 4.3.8 履历记录

**目标**

- 沉淀烧录与安装历史，支撑查询、追溯与复盘。

**核心用例**

| 用例 | 说明 |
|---|---|
| 查看烧录记录 | 查询设备、版本、结果、操作者 |
| 查看安装记录 | 查询操作系统、IP、结果、操作者 |
| 条件筛选 | 按时间、设备、软件、结果过滤 |

**输入输出规则**

- 输入：时间范围、关键字、状态、操作者。
- 输出：记录列表、结果状态、备注。

**权限要求**

- 查看：`record:view`
- 操作：按需扩展导出、删除等权限

#### 4.3.9 异常注入

**目标**

- 面向稳定性和容错性验证，提供异常模拟与监控能力。

**子场景**

- 断电模拟
- 存储不足
- 网络中断
- 权限缺失

**核心用例**

| 用例 | 说明 |
|---|---|

| 连接测试 | 在执行前验证设备或环境连通性 |
| 执行注入 | 启动异常模拟流程 |
| 查看监控台 | 右侧滑出监控台查看实时状态 |
| 停止任务 | 触发紧急恢复/终止 |
| 查看执行记录 | 查询历史异常任务 |

**输入输出规则**

- 输入：测试对象、异常类型、参数配置、执行人员。
- 输出：任务编号、执行状态、实时日志、结果状态。

**权限要求**

- 查看：`injection:view`
- 操作：`injection:add`、`injection:edit`、`injection:execute`、`injection:delete`

## 5. 非功能需求

### 5.1 性能指标

| 指标项 | 要求 |
|---|---|
| 页面首屏加载 | 常规环境下不超过 3 秒 |
| 普通列表查询响应时间 | 95% 请求不超过 2 秒 |
| 详情查询响应时间 | 95% 请求不超过 2 秒 |
| 本地数据库写入 | 单次普通写操作不超过 500ms |
| 并发承载 | 单节点支持不少于 50 个并发 API 请求 |
| 长时任务反馈 | 启动后 3 秒内应返回执行状态或日志反馈 |

### 5.2 安全性要求

- 用户密码必须加密存储，不允许明文存储。
- 接口访问基于 Token 鉴权。
- 关键接口必须做权限校验与最小权限控制。
- 敏感字段在日志中需脱敏，如密码、Token、下载凭据。
- 上传文件需限制格式和大小。
- 需具备基础防攻击策略，包括但不限于鉴权失效处理、非法参数校验、越权访问拦截。

### 5.3 兼容性要求

- 支持桌面端 Windows、macOS、Linux 打包运行。
- 开发态兼容 Chrome 内核浏览器。
- 界面在主流桌面分辨率下可正常显示。
- 关键页面需兼容 1280px 及以上宽度；对较窄窗口需保证表格滚动与布局不破坏。

### 5.4 可扩展性要求

- 新增协议类型时，允许基于现有框架扩展参数表单、连接逻辑和日志视图。
- 新增异常类型时，允许复用执行记录和监控台机制。
- 新增仓库源时，应支持在同步层扩展接入，不影响上层页面结构。
- 权限模型允许继续扩展新的按钮权限和数据权限维度。

### 5.5 易用性标准

- 列表页筛选条件布局统一，表头、分页、状态展示保持一致。
- 关键操作需提供明确成功/失败提示。
- 所有必填项、格式错误、权限不足、执行失败均需给出可理解提示。
- 用户头像、状态标签、结果标签等展示规范需在跨页面保持一致。
- 复杂任务场景应尽量采用分步配置或右侧抽屉监控，降低误操作成本。

### 5.6 可维护性要求

- 前后端代码结构需按模块分层组织。
- 核心业务模块需具备单元测试或关键路径回归测试。
- 日志记录与错误输出需支持问题快速定位。
- 需求变更需同步更新接口、权限定义和验收口径。

## 6. 项目约束

### 6.1 研发周期约束

建议按四阶段推进：

| 阶段 | 目标 | 输出 |
|---|---|---|

| 阶段三：验证能力建设 | 完成异常注入、协议验证、日志审计与回归 | 测试版本、回归报告 |
| 阶段四：交付上线 | 完成打包、部署、培训与验收 | 安装包、部署文档、验收报告 |

### 6.2 资源投入要求

- 产品经理：1 人，负责需求与验收对齐。
- 前端研发：1-2 人，负责 Electron/React 客户端。
- 后端研发：1-2 人，负责 FastAPI、SQLite、权限与业务逻辑。
- 测试工程师：1 人，负责回归和验收测试。
- 项目经理/实施支持：视交付规模配置。

### 6.3 合规性约束

- 满足企业内部账号安全和最小权限管理要求。
- 满足数据安全和日志审计要求。
- 涉及外部仓库接入时，应符合企业网络访问和凭据管理规范。
- 本地数据存储、日志留存和导出行为需遵守企业信息安全制度。

### 6.4 第三方依赖条件

- CodeArts 仓库服务可访问且凭据有效。
- Electron 打包环境完整。
- Python 3.10+ 与 Node.js 18+ 运行环境可用。
- 硬件侧烧录器、串口、网络设备、GPIO 等依赖测试环境真实可用。

### 6.5 技术约束

- 客户端基于 Electron + React + TypeScript。
- 服务端基于 FastAPI + SQLAlchemy + SQLite。
- 本期数据库以 SQLite 为主，适配单机/轻量部署场景。
- 需兼顾开发态 Web 调试与桌面端打包运行能力。

## 8. 风险与应对

| 风险 | 影响 | 应对措施 |
|---|---|---|
| 外部仓库接口变更 | 制品同步失败 | 抽象同步层，增加兼容处理和错误回显 |
| 硬件环境不稳定 | 执行与验证结果波动 | 建立标准测试环境与前置检查 |
| 权限模型复杂度提升 | 菜单/按钮/接口不一致 | 统一权限字典和回归测试覆盖 |
| SQLite 单机场景上限 | 数据量大时性能下降 | 预留迁移数据库方案 |
| 跨模块联调成本高 | 迭代延期 | 分阶段联调，沉淀固定接口契约 |
