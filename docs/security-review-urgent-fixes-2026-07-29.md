# PCIDS 非烧录流程安全与逻辑检查报告

日期：2026-07-29
范围：整体后端流程，排除烧录器驱动、烧录脚本和硬件烧录正确性。

## 结论

本轮确认的紧急问题（Critical / High）均已完成代码修复，覆盖权限提权、对象越权、异常注入恢复与敏感信息泄漏、数据库升级漏执行、退出登录/踢人后令牌仍可使用等问题。

## 已修复问题

### 1. 角色与权限提权

- 菜单和权限目录的新增、修改、删除仅允许内置 `admin`。
- 普通角色管理员只能下放自己已经拥有的权限。
- 禁止分配比操作者更宽的数据范围。
- 禁止给用户分配操作者无权管理的角色。
- 更新或删除角色前，校验目标角色是否处于操作者可管理范围。
- 拒绝不存在的权限 ID，避免生成无效角色关系。

### 2. 项目、任务和制品对象越权

- 任务详情、状态、报告、事件流、覆盖执行、终止、更新、删除和再次执行均使用同一对象范围校验。
- 制品更新、制品文件删除和项目删除均使用对象范围及项目权限双重校验。
- 禁止普通用户通过访问“尚未初始化成员”的已有项目，把自己自动登记为项目管理员。
- 只有内置管理员或明确的新项目创建者可以初始化项目成员关系。

### 3. 异常注入状态丢失与恢复

- 服务正常退出前，主动恢复仍在进行的断电、断网和权限异常注入。
- 服务启动时扫描数据库中断的注入执行记录，并尝试恢复：
  - 断电：使用持久化串口重新上电；
  - 断网：执行持久化的远端恢复脚本；
  - 权限异常：执行持久化的权限恢复脚本；
  - 存储占满：按持久化运行标记删除本次注入生成的占用文件。
- 自动探测到的电源串口、远端恢复脚本路径和存储运行标记写入执行记录，确保进程崩溃后仍可恢复。
- 恢复失败时明确标记为失败并提示人工检查，不再错误标记为恢复成功。

### 4. 注入配置敏感信息泄漏

- 注入配置和执行记录返回前递归遮蔽密码、SSH 私钥等字段。
- 非法或无法解析的配置不再原样回显。
- 操作日志对 JSON 字符串形式的注入配置递归脱敏；无法解析时整体遮蔽。

说明：运行时仍需使用注入凭据，因此数据库中的历史明文配置尚未迁移为密文存储。当前已封住 API 和操作日志外泄路径；后续可单独实施存量数据加密迁移与密钥轮换。

### 5. 数据库升级被初始化标记跳过

- 首次初始化标记现在只控制默认业务数据创建。
- 权限菜单同步、默认角色权限、历史任务状态/时长、菜单标签、任务及注入编号等幂等迁移会在每次启动执行。
- 新增 `users.token_version` 列由 SQLite 启动迁移自动补齐。

### 6. JWT 无法强制失效

- JWT 加入用户令牌版本号。
- 每次鉴权校验令牌版本与数据库是否一致。
- 退出登录、管理员踢人、修改密码、重置密码都会递增版本，使该用户此前签发的全部令牌立即失效。
- 部署前签发、没有版本号的旧令牌会被拒绝，用户需要重新登录。

## 验证结果

- 紧急修复专项测试：45 项通过。
- 后端全量测试首次运行：574 项通过，2 项失败。
- 2 项失败均为已有 Win7 打包策略冲突：当前配置包含 CodeArts 浏览器运行时，而旧测试仍要求 `tools/` 资源必须全部外置。
- 后续全量运行还观察到 CodeArts Web 测试桩与当前响应校验不一致、文本编码归一化用例失败；相关文件在本轮开始前已有修改，不属于本轮安全修复范围。
- 所有本轮修改的 Python 文件均通过语法编译和 `git diff --check`。
